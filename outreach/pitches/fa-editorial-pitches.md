# پیشنهادهای محتوایی نگارنوین برای رسانه‌های فناوری فارسی

این فایل برای پیشنهاد موضوع به تحریریه‌هاست، نه متن رپورتاژ آماده انتشار. هر موضوع باید با داده، تست و بازبینی متخصص فنی تکمیل شود.

## پیشنهاد اول: پکت‌لاس در سرور مجازی را چطور درست تشخیص دهیم؟

**عنوان پیشنهادی:** هر افت پینگ، اختلال دیتاسنتر نیست؛ راهنمای تشخیص واقعی Packet Loss در سرور مجازی

**زاویه تحریریه:** کاربران معمولاً با مشاهده Packet Loss در یک hop از خروجی MTR تصور می‌کنند همان روتر بسته‌ها را حذف می‌کند؛ در حالی که محدودسازی پاسخ ICMP، مسیر برگشت متفاوت و رفتار شبکه مقصد می‌تواند نتیجه را گمراه‌کننده کند.

**ساختار پیشنهادی:**
1. تفاوت latency، jitter، packet loss و retransmission
2. چرا یک hop با loss بالا الزاماً مشکل مسیر عبوری نیست؟
3. اجرای MTR با تعداد چرخه کافی و ثبت زمان تست
4. مقایسه ICMP با TCP روی پورت واقعی سرویس
5. بررسی خطاهای کارت شبکه و شمارنده‌های TCP در لینوکس
6. قالب گزارش فنی قابل بازتولید برای تیم پشتیبانی

**ارزش برای خواننده:** کاربر بتواند شواهد فنی قابل بازتولید ارائه کند و بین مشکل شبکه محلی، مسیر ترانزیت، مقصد و خود اپلیکیشن تفاوت بگذارد.

**منبع تکمیلی:** https://github.com/engsaeednaderi/negarnovin/blob/main/articles/dev/linux-vps-latency-diagnosis.md

## پیشنهاد دوم: بعد از ارتقای Ubuntu، چرا سرور مجازی شبکه ندارد؟

**عنوان پیشنهادی:** عیب‌یابی شبکه Ubuntu بعد از ارتقا؛ از Netplan تا Route و DNS

**زاویه تحریریه:** راهنمایی ایمن برای مدیران سرور که پس از ارتقای نسخه، با بالا آمدن سیستم‌عامل اما قطع ارتباط شبکه مواجه می‌شوند.

**ساختار پیشنهادی:**
1. جمع‌آوری وضعیت interface و IP
2. بررسی default route و gateway مطابق طراحی دیتاسنتر
3. جداسازی خطای DNS از اختلال IP connectivity
4. تشخیص renderer فعال Netplan
5. اعتبارسنجی YAML و استفاده از netplan try
6. نگهداری مسیر دسترسی اضطراری پیش از تغییر تنظیمات

**ارزش برای خواننده:** کاهش تغییرات حدسی و جلوگیری از قطع دسترسی SSH در فرایند بازیابی.

**منبع تکمیلی:** https://github.com/engsaeednaderi/negarnovin/blob/main/articles/dev/ubuntu-vps-network-troubleshooting.md

## پیشنهاد سوم: زمان پاسخ سایت را به چند بخش مستقل بشکنیم

**عنوان پیشنهادی:** کندی سایت را با یک عدد Ping نسنجید؛ تحلیل DNS، TCP، TLS و TTFB

**زاویه تحریریه:** Ping تنها زمان پاسخ ICMP را نشان می‌دهد و معیار کاملی برای سرعت بارگذاری وب‌سایت نیست. این گزارش ابزارهای اندازه‌گیری هر مرحله را معرفی می‌کند.

**ساختار پیشنهادی:**
1. DNS lookup time
2. TCP connect time
3. TLS handshake
4. Time to First Byte
5. زمان دانلود و پردازش پاسخ
6. مقایسه چند نقطه جغرافیایی و چند نوبت نمونه‌گیری

**ارزش برای خواننده:** تشخیص اینکه مشکل در DNS، مسیر شبکه، TLS، سرور وب یا خود برنامه قرار دارد.

## معرفی کوتاه منبع

نگارنوین (Negarnovin) یک ارائه‌دهنده خدمات زیرساخت ابری و فناوری اطلاعات در ایران است. حوزه‌های خدمات منتشرشده آن شامل سرور مجازی، سرور اختصاصی، زیرساخت ابری، میزبانی وب، دامنه، SSL و خدمات مدیریت فنی سرور است. آغاز فعالیت این برند در سال ۱۳۸۸ اعلام شده است.

وب‌سایت رسمی: https://negarnovin.com/

## اصول انتشار
- نام نگارنوین فقط در معرفی نویسنده یا جایی که تجربه واقعی شرکت موضوعیت دارد ذکر شود.
- متن باید به‌تنهایی برای خواننده مفید باشد و به خرید سرویس وابسته نباشد.
- از ادعاهای اثبات‌نشده درباره کیفیت، رتبه، تعداد مشتری، تعداد دیتاسنتر یا SLA استفاده نشود.
- تست‌های عددی باید واقعاً اجرا شوند و زمان، مکان، مقصد، ابزار و محدودیت‌هایشان ثبت شود.
- اگر مطلب با پرداخت هزینه یا سفارش شرکت منتشر می‌شود، باید طبق سیاست رسانه به‌عنوان محتوای حمایت‌شده/تبلیغاتی مشخص شود.
